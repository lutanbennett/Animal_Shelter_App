- [x] Change is described in one sentence, and it matches what the backlog item asked for: the summary PDF's line height is declared per text style instead of on the page, which fixes both the name/subtitle overlap and the missing footer — they had one cause; and, added at Lutan's request, the profile photo is taken from Drive's JPEG thumbnail so HEIC and large photos are no longer silently dropped

## 4. Functional checks

The PDF was checked as the brief asked: by rendering the real exported
`renderResidentSummaryPdf()` against stub `ResidentArchiveRecord`s (bundled with
esbuild, `server-only` aliased out, no Drive or database) and opening every page
of every output. Before the fix the same harness reproduced both bugs: name over
subtitle on page 1, and no footer text on any page of any render.

- [x] Happy path works end to end: Latin-named resident (`latin.pdf`, production, 2 pages) — name on its own line above the subtitle; footer `Lanna Care for Animals · Chai (R-0042) · generated 24 Sept 2026` with `1 / 2`, `2 / 2`
- [ ] Data persists — reload the page and the change is still there — n/a: no stored data; the PDF is regenerated from the record each time
- [x] Profile photo embedding: every stub re-rendered with a JPEG profile photo (`public/lca-logo.jpg` as a data URI) — the photo prints beside the heading and every PDF grew by the image's size. The photo-selection chain was run through the real `archiveDeceasedResident()` against a fake Drive client (bundled with esbuild, Drive / record / PDF modules replaced): JPEG thumbnail → embedded without fetching the original; WebP thumbnail, a throwing thumbnail call, or no thumbnail → falls back to the original and embeds it; no thumbnail with a HEIC original, and a failed thumbnail with a 5 MB original → no photo, archive still `ok`, and one `console.warn` naming both reasons
- [ ] Create / edit / delete all exercised — n/a: the create/refresh/delete paths around the PDF are unchanged; only what it embeds changed
- [x] Empty state renders sensibly: every section empty except one placement (`wrap.pdf`, zero weights) — "No … recorded." lines render at the new line height with no clipping
- [ ] Invalid input is rejected with a readable message, not a crash — n/a: no input; the PDF takes an already-validated record
- [x] Boundary cases checked: Thai name in brackets (`thai.pdf`); Thai-only name in heading and footer (`thai-only.pdf`, `มะลิ (R-0042)`); a name long enough to wrap to two lines in the 20pt heading (`wrap.pdf`) — both lines clear of each other and of the subtitle; a 90-row weight table across four pages under the DEV watermark (`long.pdf`) — footer `… · DEV` with `1 / 4` … `4 / 4` on every page, watermark still on every page, table rows unchanged
