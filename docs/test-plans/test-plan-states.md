## Defects found

| # | Severity | What | Status |
|---|---|---|---|
| 1 | high | The checker had two states where the work has three. Section 8's deploy gates cannot be true at PR time, so they were being written `n/a` — a falsehood in a box labelled "did not apply". Left alone it would have taught people to write `n/a` for things they simply had not done, which is the exact habit the check exists to prevent | fixed — `deferred: <owner>`, accepted only under section 8 |
| 2 | high | A *correct* plan is red for most of its life, and the checker printed one flat list in which "nobody has looked yet" was indistinguishable from "a check was skipped". Red carried no information, and an uninformative red gets ignored — which would matter enormously if this ever became a blocking check | fixed — output grouped into problems / awaiting a person / deferred, with a headline saying which |
| 3 | medium | The manual-verification checkbox could only be ticked by the person who looked, while the text above it said to write `n/a` when there was nothing to look at — so a plan with a genuinely empty manual list could never go green. The two-signature split undercut itself | fixed — the checkbox now says whoever filled the plan may tick it when the list is empty |
| 4 | medium | Section 6's "checked from a second, unrelated page" could be satisfied by reading the file, which proves only that you did not edit it — not that the value it supplies at runtime is still the one the other page expects. The weaker reading is the tempting one | fixed — now says by loading the page, not by reading the file |
| 5 | medium | Nothing asked whether a boundary test discriminated. A regression test written faithfully from a bug report can pass while the fault survives, because the reported case is the one that was noticed, not the one that moves | fixed — section 8 banding line, with the `dueState()` case as the worked example |
| 6 | low | Nothing said evidence must be regenerated rather than hand-maintained, so an evidence block could drift from the run it claimed to record — the precise failure it existed to prevent | fixed — section 8 line requiring unedited tool output |
| 7 | medium | An undated `pending:` or `n/a:` signature failed with "no Manual verification by … Date" — an error pointing at a missing date for a line that was correct, on a form the template itself implies. The workaround (a meaningless `Date: —`) was discoverable only by reading other plans | fixed — the parser falls back to a bare line for `n/a`/`pending`; a bare name still needs its date |
| 8 | low | `deferred` with no owner reported "not marked `n/a`", pointing at the wrong problem — the same class of bug as the bare `n/a:` fixed on the previous PR | fixed — matched on the word, not on a well-formed value |
| 9 | medium | The two new rules fought each other: evidence must be pasted unedited, but pasted checker output quotes the checker's own error messages, which contain the template's angle-bracket name and date tokens — so the placeholder check flagged a faithful record of a run as an unfilled template. Found by regenerating this plan's own evidence block, which is what rule 6 asks for | fixed — fenced code blocks are skipped for placeholder and checkbox scanning; a token outside a fence still fails, verified both ways |
| 10 | low | Writing up defect 9 reproduced it: naming the tokens in prose, outside a fence, failed the check. Correct behaviour, but it means any plan *discussing* the template needs the fence too | accepted — the checker is right; the wording avoids the literal tokens instead |
| 12 | high | The working-tree fallback silently dropped a plan that was modified but not staged. `git()` trims the whole output, eating the leading space of porcelain's ` M path`, and the fixed `slice(3)` then cut one character into the path. Only the first line is affected, so it looked intermittent. Worst possible shape: it told someone who had filled in a plan that they had not, under instructions to copy the template over it — following that advice literally would destroy their work. Local only, which is exactly where the fallback exists to help | fixed — parsed by matching the status field rather than a fixed offset; eight status forms verified including renames |
| 11 | high | The role matrix listed a `resident` role that does not exist, and omitted `management`, which gates every `/management/*` page. Derived by grepping for quoted strings rather than reading `app_role`, so it matched a query about animals and missed a role added by a later migration. Wrong in both directions: a row nobody can meaningfully tick, and a missing row for the role most likely to be in an access bug. Every checklist written so far carries it | fixed — matrix corrected and the two migrations cited in the template, so the list is read rather than re-derived |
