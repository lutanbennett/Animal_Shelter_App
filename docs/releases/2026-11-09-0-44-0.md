## What shipped, in a sentence

Fourteen release notes. **Words and photos bound for the public website now wait to be read before
anyone outside can see them**, under a new card — *Approve public text* — and a screen of the same
name. **Suppliers leave Contacts** and become their own list with their own card. **The user manual
now follows your cards** rather than showing every screen the shelter has, and *Cards at a glance*
lists only the cards you hold. Settings → Diets opens on one card of its own. Three narrower screens
stop refusing or misinforming a login whose cards are narrower than the page assumed, and every home
screen gains User manual, Release notes and Change password tiles — which is how a login with no
left-hand menu can now change its own password.

**Counted from the entry rather than described from memory:** fourteen notes, five card-tagged
(`approve_text`, `diet_settings`, `translations`, `propose_translations`, `suppliers`, `website`), one
`admin: true`, eight plain, and `unreleased` empty after the cut. Five say in their own text that
their Thai has not been checked by a Thai speaker.

## Why it mails

Lutan asked for it in words: *"Let's do a major release with email sent out. Record gaps and
proceed"*. `major` in this repo means *worth an email*, not semver major, and until go-live a mailing
release bumps the **middle** number (`src/lib/releases.ts`'s own numbering note), so `0.43.6` →
`0.44.0`. The runbook forbids offering "major or minor" as the question; he named the email himself,
so it was never asked, and the same sentence pre-answered the `pending:` test-plan decision that cost
`0.43.6` a touch.

**Asserted with a control, not read off the flag:**

```
ok   mail PRESENCE: majorReleasesSince(previous) is exactly the new version  [["0.44.0"]]
ok   control: from further back, an older major release is still found  [0.43.0 in ["0.44.0","0.43.0"]]
```

An always-empty function would satisfy the first and fail the second.

## A note was owed, and this cut added it

`site-content-create-feature` wrote its release-notes line as `n/a` because migration `0344` was not
on production, so the button it added would not have worked there. **This release applies `0344`**, so
the step closed and the note went into `unreleased` **before** the cut ran. It covers Settings →
Website saying plainly that nothing is set up yet and offering a *Create the website settings*
button — both halves of `#ipf1z` as a user meets them.

**That is why the cut had to be verified against a built base.** `--verify` compares against
`origin/main:src/lib/releases.ts`, which stops being the pre-cut state the moment a cut adds a note:
*every note carried across character-identical* and *nothing invented* would have failed on
`[14 vs 13]` while fifteen of seventeen passed. Waving those two past is exactly how a cut loses a
note. The base was built explicitly and **all 17 passed at `[14 vs 14]`**.
