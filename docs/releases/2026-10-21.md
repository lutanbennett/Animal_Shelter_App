## THE FINDING: a directory in a `-- consumer:` header can never read `live`

**Nine `-- consumer:` warnings were predicted before the apply, all nine appeared
exactly as predicted — and four of them carry no information whatsoever.**

`consumerState` asks whether a migration's declared reader was already live by
comparing `git show <ref>:<path>` at the live release and at `origin/main`. For a
**file** that is right. For a **directory**, `git show` prints a tree listing
whose first line is `tree <ref>:<path>/` — **the ref is in the text** — so the two
always differ and the path reports `differs` however little changed inside it.

**Proved rather than inferred**, which matters because the obvious reading of a
warning is that the directory changed:

```
worker/   git diff --name-only 1de7bdb4..HEAD -- worker/   →  (empty)
worker/   consumerState                                     →  differs
```

The four of this kind were `src/app/clinic-visits/`, `src/app/admin/status/`,
`worker/` and `src/app/admin/website/`. The five file-valued paths
(`src/lib/site/content.ts`, `src/app/adopt/PublicFooter.tsx`,
`src/app/about/page.tsx`, `src/app/donate/page.tsx`, `src/lib/status/health.ts`)
warned for the right reason: each is a reader arriving in this same release, which
is the safe direction by construction.

**Wrong in both directions, not merely noisy.** A tree listing holds only *names*.
Even with the ref stripped, a directory whose file contents changed but whose
filenames did not would read `live` — a false reassurance in the one direction the
check exists to catch.

**Not fixed here, deliberately.** It never blocks and never changes what is
applied, so it is noise rather than risk, and a release is the wrong place to
change the behaviour of a release-time check. Filed on the `backlog` branch with
the two tempting wrong fixes named: making directory paths silent (which trades a
vacuous warning for a vacuous `live`) and inferring consumers from the SQL (which
was considered and rejected in `docs/decisions/2026-10-02-migration-consumer-header.md`).

**Why it earns this much space:** this is the signal that decision added to catch a
real ordering fault, and **a check that warns every time is one people stop
reading** — the same failure the `test-plan` job's old `continue-on-error` had.
