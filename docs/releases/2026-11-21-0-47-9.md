## What this release actually carries: three multi-tenant fixes

- **`0430`** — `public_site_content` **answered every shelter's row to everyone.** The view is owner-run,
  so `0392`'s restrictive shelter policy never applied to it, and `readSiteContent()` takes `.limit(1)`,
  so a second shelter's public site could have shown an arbitrary shelter's content — including its logo.
  Measured on dev inside `0429`'s harness: anon got all 6 rows **with** and **without** a shelter header
- **`0431`** — `set_shelter_logo()` was modelled on `set_hero_photo()` and copied its flaw. `where id =
  true` inside a `security definer` function matched **every** shelter's `site_content` row, so one
  shelter's Admin would have overwritten every other shelter's logo. Caught by
  `supabase/harness/shelter_logo.sql` (*"set touched the other shelter"*)
- **`0432`** — the same flaw in its model, `set_hero_photo()` (`0274`, `0351`), and in
  `approve_website_draft()` (`0315`). Swept for the shape and fixed

**Why these were safe to apply BEFORE the Worker deploy, read rather than assumed.** `0430` gives anon no
rows without an `x-shelter-id` header, which is the shape that blanked the public website when `0392`
landed. The **live** Worker already sent that header — `git grep x-shelter-id 3d93e90ec -- worker/` names
`worker/index.mjs` and `worker/shelter.mjs` at the then-deployed SHA — and `check-release-order.mjs`
reported ok in both directions on **both** production and UAT.
