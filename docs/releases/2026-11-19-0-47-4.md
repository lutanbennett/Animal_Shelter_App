# Release smoke test — `0.47.4`

Copied from `docs/release-smoke-test.md` and filled in against `lannacareforanimals.org`
after the deploy. **A record, not a gate**, and nothing in CI checks it.

**`0.47.4` is a minor release and it mailed nobody.** Lutan said only *"lets try a new release"*,
which does not settle the mail, so he was asked the one question a cut must always ask — *should this
release email you?*, with what the mail would contain and that it cannot be unsent — and chose **no
email**.

**It landed completely, which the two before it did not.** Every site and every Worker is on one
commit, and **production's fallback Worker went from `0.47.2` straight to `0.47.4`**, closing the one
thing `0.47.3` could not finish. The deploy script said so itself: *"no major release new to
production (was 0.47.2), so no email"*.

## What shipped, in the two notes a user sees

Both `admin: true`, so **only Admin sees them**, and both were written by the streams that built them
rather than composed at the cut:

1. **A second shelter can now keep its photos in its own Google Drive account.** A photo added for one
   shelter goes into that shelter's own Drive folder and is never filed in another shelter's. Nothing
   changes for Lanna
2. **Settings → Product admin: a product administrator who has verified with their authenticator app
   can now give a new shelter its Admin role and link a login to it**, so someone can sign in to that
   shelter. The login must already exist (you paste its account id): this screen does not create logins
   or send invitations, and the screen does not yet show which of the two steps a shelter has had

**Both notes' audience was driven in both directions rather than reasoned.** `/releases` was fetched on
a worktree dev server as Admin (all four note probes present) and as a login holding exactly one card
(section and title present, **all four absent**), with `0 x [object Object]` and `0 x undefined<` on
both. Two separated probes per note, so a half-rendered note would have shown.

### The gap that got wider, not narrower

**Nobody is a product administrator on production, and no script places the first one** (`#pdmin`,
filed during `0.47.3`). `0411` seeds nobody on purpose and its insert policy asks `is_product_admin()`,
so the list cannot bootstrap itself through the app.

**This release publishes a second capability on that same screen**, so where `0.47.3` left one
announced-but-unreachable feature, there are now two: creating a shelter with its addresses, and giving
it an Admin role and first login. **The onboarding chain is now built end to end in code and cannot be
started by anybody.**

Two things already known make the first PADMIN a considered choice rather than a formality, both from
`#shmgt`'s own tail: a PADMIN who is not also a shelter Admin **reaches the screen only by typing its
address**, and a PADMIN with no authenticator **cannot set one up themselves**, since first setup is
opened by a shelter Admin. Every write on that screen needs `aal2`.

### The IPv6 fix was applied mid-release, and the result is now measured rather than argued

`0.47.3` ended because the deploy machine prefers IPv6 and has none; Lutan applied a fix and reverted it
afterwards, so this release began with the fault back. **What happened is a cleaner experiment than
anything the last release produced:**

| | Font fetch | Cloudflare API |
|---|---|---|
| **With IPv6 preferred** (`0.47.3`, and the first half of this one) | 3 failures | 2 failures (one DNS, one timeout) |
| **With IPv4 preferred** (second half of this release) | 0 failures | **0 failures** |

And the part that was genuinely surprising: **the font fetch succeeded four times running even with
IPv6 preferred** — the gates build in a fresh worktree with no `.next` (so fonts were fetched, not
cached), the test Worker build, and two more. **So the font half is intermittent, and the Cloudflare
half is the one the preference reliably breaks.** `0.47.3`'s record called the whole thing one fault;
that was right about the cause and too confident about the symptom.

**The permanent fix is to stop the build needing the network at all** — `next/font/local` with the font
files in the repository — which is a code change and not a release-time one. Worth a backlog item, and
it would remove the need to touch a system setting around every deploy.

### Mistakes of the release manager's own

1. **The `netsh` command was handed over with a trailing backslash**, a copy artefact from the code
   block rather than from Lutan's typing, and it failed with *"The parameter is incorrect"*. He spotted
   it and removed it himself. **A command handed over is not verified until it is verified as the
   person will paste it.**
2. **A build was started without confirming it had started.** The first UAT Pi attempt was launched and
   reported as away on the strength of the launcher returning; it never ran. The second attempt was
   confirmed by reading the log's byte count, which is the check that should have been there the first
   time — and is the same shape as `0.47.2`'s *"the launcher `ssh` returning is not the build ending"*.
