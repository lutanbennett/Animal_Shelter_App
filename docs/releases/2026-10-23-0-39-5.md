**One check this release added, and it is the kind worth keeping.** #881's stated
production apply plan was *"roles are matched by key so a missing role is skipped"*.
That covers a role that is **absent** but not the case that would actually hurt: a role
that **exists** on production and is skipped anyway by `kind <> 'fixed'` or
`archived_at is null`, which would silently lose its tiles once #882's code went live.
Production's roles could not be read — all the relevant check scripts are hard-locked to
the dev project, and that guard was left alone rather than worked around — so it was
established from the schema instead: `0132_permission_tables.sql:91` carries the CHECK
constraint `(kind = 'fixed') = (key in ('admin', 'public_viewer'))`, making `fixed`
**impossible** for any other key, on production as much as on dev, and all five of
`0251`'s roles are created by long-applied migrations (`0132`, `0136`, `0141`, `0143`).
**Not a risk.** The gap was in the plan's reasoning, not in the migration, and
"dev behaved well" is a different statement from "production cannot differ".
