## Why it does not mail

Lutan asked for it in words, unprompted: *"Let's do a minor release no email. Outstanding open tests
logged as gap"*. `major` in this repo means *worth an email*, so `major: false` and the **last** number
moves: `0.44.1` → `0.44.2`. The runbook forbids offering "major or minor" as the question; it was never
asked.

**That one sentence answered both decisions a release normally costs him — the second release running.**
The email was the first; *outstanding open tests logged as gap* pre-answered the `pending:` test-plan
decision that section 3 would otherwise have put to him.

**Asserted with a control, not read off the flag:**

```
ok   mail ABSENCE: majorReleasesSince(previous) is empty  [[]]
ok   control: from further back, an older major release is still found  [0.44.0 in ["0.44.0"]]
```

**And then all three deploys said it themselves**, which is the reading that matters:

```
deploy: no major release new to test (was 0.44.1), so no email.
deploy: no major release new to production (was 0.44.1), so no email.
```

### Correcting `0.44.1`'s record and handover: test DOES print a mail line

### The three stylesheet sizes differ, and that is not a fault

Production `99854`, test `99839`, UAT `99876`. The three environments bake different values into the
CSS, so the content hashes and byte counts legitimately differ. **The check that settles it is
`check-assets.mjs` on each clone**, which compares the *served* stylesheet with *that clone's own
build* — and all three read *identical to the build*. A size that matches another environment's would
be the thing to worry about, not a size that differs.
