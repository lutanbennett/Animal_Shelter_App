## What this release was for

**Two notes a person sees, both `admin: true`, and one fault fixed that had no note.**

1. **A product administrator can create a shelter's first Admin login** (#1750), temporary password
   shown once, instead of needing a developer. This closes `#flogn`, which `0.47.5`'s handover named
   as the clearest next job and as needing Lutan's decision first. He gave it: a narrow
   product-administrator definer function (`0425`), **not** a widening of `security.createUser`,
   which would have let any shelter's own Admin mint logins.
2. **A Website save on a shelter with no website-settings row now says so** (#1747), and says to ask
   the product administrator, instead of reporting a save that kept nothing.

**And the reason this release existed at all: `#plhbd`.** `cooperjaidee.org` went live in `0.47.5`
with every button on it refused while every page rendered. Lutan found it minutes after that deploy,
doing exactly the saving proof `docs/domain-checklist.md` section F insists on. The fix (#1749) was
merged last night and could not take effect without a new build, because the allowed-origin list is
baked at build time. **This is the build that carries it.**

### The `#plhbd` fix was PROVEN, not inferred, and that is worth copying

The page rendered perfectly while the fault was live, so loading it proves nothing. Rather than wait
for a person to press a button, the baked list was read **out of the running production build**:

```bash
ssh lanna-pi-mesh 'cd ~/Animal_Shelter_App && node -e "…require(\"./.next/required-server-files.json\").config.experimental.serverActions.allowedOrigins"'
["lannacareforanimals.org","www.lannacareforanimals.org","cooperjaidee.org","www.cooperjaidee.org"]
```

Before the fix that list held the first two only. `.next/required-server-files.json` is where Next
stores the value it was built with, so this is the thing the origin check actually reads.

**Also confirmed at the source of the fault:** `~/Animal_Shelter_App/.env.production.local` on the Pi
now contains `PLATFORM_HOST`, which it did not before (that absence was the fault). **Test and UAT
contain none, which is correct** — neither declares a platform host, and the PR's blast-radius note
said their behaviour would be unchanged.

**What this does NOT replace:** the saving proof itself. A baked list is strong evidence the refusal
is gone; only a real save proves the whole path. It is item 1 of the gaps below.

## The one thing this release did not get to verify, and it is somebody else's find

**`#hostx`, filed by a planner this morning while this release was being cut:** nobody could sign in on
`test.lannacare.org`, and it was **one missing `shelter_hosts` row** — the Worker maps the request host
to a shelter, a miss sends no `x-shelter-id`, and since `0392` no shelter header means no rows. **To
every user that looks exactly like their own account having been deleted**, which is what it cost Lutan
this morning.

That item asks, in terms, that UAT and production be checked the same way before being assumed fine.
**They were not, and this is why:** no script in this repository reads `shelter_hosts`, and an ad-hoc
production read is refused. What was done instead is **behavioural evidence, recorded as that and not as
a check**: production's `/` serves the shelter's own name out of the database, which the header has to
resolve for; and production signs people in all day. **Nothing was established about UAT's host at all.**

**This release did not make it worse.** `0426` keeps `resolve_shelter_host` alongside the new
`resolve_shelter_site`, and both need the same row — so the set of hosts needing a row is exactly what
it was. The real item is the check `#hostx` asks for, and it stays open.
