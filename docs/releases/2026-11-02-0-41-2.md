### The two clones built different stylesheets, and it is harmless — but it retires a line in the last record

`check-assets` passed on both hosts, each against **its own** build, which is what it asserts. But the two differ: production serves `3-dgwzl6jfh0i.css` at 98735 bytes and test `2_kdr9t9pti8v.css` at 98670. `0.41.1`'s record said *"the same filename and byte count on both is expected here, not a mix-up"*. **That is not a property to rely on**, and this release is the counter-example.

Measured rather than reasoned about. Each clone holds exactly one CSS chunk, both working trees are clean and both are at `9cd14859`. Diffed, production's build carries two extra rules and nothing else: `.z-2{z-index:2}` and `.\!p-9{padding:calc(var(--spacing) * 9)!important}`. Neither class name appears anywhere in the source **except as accidental byte sequences inside two manual screenshots**, `public/manual/resident-photos.png` and `public/manual/blood-test-new.png`, which both clones hold identically. So Tailwind's source scanner extracted two candidates from binary noise on one build and not the other. **No component uses either class, so nothing renders differently** — but the cross-host byte comparison is not a check, and a future record should not present it as one.
