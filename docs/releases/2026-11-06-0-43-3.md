## An ordinary release, and saying so is the finding

**`0.43.2` was asked for in almost exactly these words and was secretly the domain cutover.** So the
first thing done this time was the check that caught it, before anything was cut:

- `git log --oneline -1` → `518290a7 Merge pull request #1311 … claude/public-wordmark-home`
- the four PRs in the range read as a Dependabot Actions bump, a locked landing page, a public
  wordmark and a developer-tooling guard
- **nothing in the range changes a host, a domain, a policy, an activity, a card or a cell**
- production: `318 applied, 0 pending`, drift `0` in both directions

**That is a plain cut with a plain deploy, and it took one command to establish.** The last
handover's *"one thing to read before your next cut"* paid for itself on the very next release, which
is the test of whether a handover is worth writing.

sign-in page — what every signed-in person and every anonymous visitor meets — so a card tag would
have hidden them from exactly the people who see the change. Widening is this repo's safe default.

**Nothing else in the release is user-visible**, and that is written down rather than inferred: #1312
is a developer-tooling guard (`guarded-install` refuses while a server holds the checkout) and #1161

### The deferred-note review

`check-deferred-notes.mjs` flagged **two** of four candidates as possibly owing a note; **neither
did.** Both are the boilerplate false positive four handover editions have warned about — the excerpt
it prints is the **checklist template's own guidance text**, not the plan's answer.
`lock-page-coming-soon` had in fact **ticked** its release-notes line and its note is one of the two
shipping here; `record-0-43-2` is the last release's docs-only record.

**`--base` was NOT needed, breaking a three-release run.** The rule behind it is worth keeping:
`--base` is needed when the cut itself writes a note, because `origin/main` then no longer holds what
the new entry should be compared against. This cut wrote none.

## The touches this release cost

**The target is two. This one cost one, and the extra round trip was free.**

1. **The email answer** — given unprompted in the request itself, so it cost nothing.
2. **The production Worker deploy** — his one standing job.

No third was asked for: no migration to apply, no decision to put to him, no step needing his
password or a dashboard. The *"is it my turn soon?"* and *"Yes, carry on"* exchanges were him asking
and answering about his own one job, not extra work created by the release.
