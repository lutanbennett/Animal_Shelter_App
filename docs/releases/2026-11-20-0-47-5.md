## THE NOTES ARE THE STORY OF THIS RELEASE: `unreleased` WAS EMPTY

**Eleven streams, 23 PRs, and not one touched `src/lib/releases.ts`.** This is the state the procedure
warns about — *"an empty `unreleased` is not proof that nothing user-visible shipped"* — and it was
measured rather than accepted:

- `git log bc13394ee..HEAD --name-only -- src/app src/components src/lib/manual src/lib/i18n worker`
  returns **four** user-facing changes: the platform console (#1739, #1742), the stocktaking failure
  message (#1740), the font swap (#1725).
- `check-deferred-notes.mjs` reads **64** changed test plans and finds **every one** answered the
  release-notes line `n/a`, each with a reason. Exit 0 — nothing held back wrongly.

**The `n/a` answers were right about shelter users and wrong about Admin.** Three of the four are
genuinely invisible: the fonts must render identically, the stocktaking message cannot be reached
(`0417` backfills every shelter's settings row), and the console is a product administrator's screen,
today one person. **The fourth is not invisible to Admin — this release deletes the Product admin tile
from Settings and the page behind it.** Lutan had used that page hours earlier; without a note he
would have met a gone tile and a 404 with nothing to explain it.

**Writing the notes was not optional: `cut-release.mjs` refuses to write while `unreleased` is empty.**
A zero-note release could only be had by going round the tool, and an entry with a title and no lines
reads as "nothing shipped" for a release carrying eleven streams and six migrations.

**The note considered and rejected** was the stocktaking one — `0417` backfilled every shelter, so
nobody can reach the new message, and a note would have invented visibility.

**This is a process fault, not a release fault, and it belongs to the planner:** `n/a` is answered
about shelter users while `admin: true` notes exist for precisely this case.

### The deferred-note gate is a real gate, not advisory

`cut-release.mjs` **refused outright** — *"16 PR(s) above wrote n/a for a step that may close in this
release"* — and wrote nothing until all 16 were reviewed by name through `--deferred-reviewed`. Two
remain open (`calendar-connect-screen`; `stocktaking-silent-save`), eleven owe nothing because their
note already shipped or their reason quotes the rule rather than naming a step, and the rest were
closed by this release's two notes.

### The dry-run went red, and the correct action was to apply

`0420` reported *"cannot change return type of existing function"* on **both** databases. That is the
documented caveat — each file is rolled back before the next runs, so `0417`'s drop-and-recreate of
`product_admin_shelters()` was gone by the time `0420` built on it. **The runner diagnosed itself, and
it was checked rather than trusted:** `0417` drops the function and recreates it with thirteen
columns, and `0420`'s return shape is character-identical, so `create or replace` succeeds once each
file commits. It did, on both.

**Applying before the deploy was safe, reasoned from the files rather than assumed.** `0419`–`0421`
add a `set_config(..., is_local => true)` of the shelter header *inside* functions that already check
product administrator and `aal2`; who may call them is unchanged. `0.47.4`'s console called some of
the same functions, so the change **repaired** them — applying early fixed Lutan's console on the old
release.

**`0417` had not run on production before this release.** A planner message understated the pending
set as four files; `--status` read six. It matters beyond bookkeeping: the stocktaking note was
declined because `0417` backfills every shelter, and on production that backfill happened *during*
this release.

### What did NOT recur

- **The font fetch did not fail once**, across six builds. `#fntlc` landed in this release (#1725), so
  `layout.tsx` uses `next/font/local` and no build needs Google Fonts at all
- **The Cloudflare API hostname did not fail once.** `--plan` showed wrangler authenticating from a
  scoped **API token** in `.env.deploy.production` rather than its own OAuth login, and the upload did
  not expire mid-build — the `0.47.1` failure did not happen
- **IPv6 is still preferred on this machine and it still has no IPv6 address.** Lutan reverted the
  `netsh` fix after `0.47.3`, so the fault is live. **Every request in this release used `curl -4`**,
  which is the working habit until the preference is changed for good
