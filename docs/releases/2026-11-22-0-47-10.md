## The one note this release publishes

> *"The Shelter logo card on Admin → Website now accepts a logo up to 1 MB (it was 15 MB). A logo only
> shows about 64 pixels wide, and every visitor to your public website downloads it, so a big file just
> slows the pages. A larger file is refused with a message saying so, in English and Thai."*

`cards: ["website_photos"]`, so it shows on `/releases` to a login holding the Shelter logo card — and to
Admin, who sees everything through the `perms.isAdmin` short-circuit. Written by #1816, carried across
character-identical, asserted by the cut's 17 checks.

It is the second note in two releases about the same card: `0.47.9` announced the card and this one caps
what it accepts. **The user-visible change is a refusal that did not exist yesterday**, which is the part
worth knowing when reading the note.

## What else is in it, and the one piece worth naming

Almost nothing a shelter user can see: release and operator checks (#1813, #1814, #1815, #1819), two
documents PRs (#1808, #1817), the per-shelter primary-host flag (#1809), a Worker CPU measurement
(#1810), three Worker secret **names** registered but not set (#1811), and the shelter Drive/Calendar
connect flow (#1818) — which is this release's **test gap** rather than its feature.

**`0434_tenancy_catalogue_flags.sql` (#1812) is the piece worth naming, because it closes a fault in the
release process rather than in the app.**

- `product_admin_login_grants` had row-level security on and **no `definer_all` policy** (from `0425`), so
  every view over it read 0 rows for the re-owned role — a blank page, **not a leak**. `0434` adds it.
- `set_shelter_logo()` was left **owned by `postgres`** by `0429`: the one flag `0.47.9` itself introduced.
  `0434` re-owns it to `rls_definer`, which `0428` and `0433` already do and which its own model
  `set_hero_photo` already had. `0431` had already scoped the function's body to the caller's shelter, so
  this is braces to a belt that was on.
- `product_admin_permit_first_login` **stays** owned by `postgres`, deliberately — it reads `auth.users`,
  which a re-owned role is refused (42501) — and #1812 added it to the lint's allow-list with that reason,
  beside the six comparable functions already there.

**Why that matters beyond the schema:** `check-tenancy-catalogue.mjs --strict` is a prescribed release step
that went **six releases unrun** because it exited 1 on something correct. `0.47.9` found that, recorded it
and filed `#tncy3`; **this release fixes it, and the lint now exits 0 on all three databases** — the first
green since `0.47.2`. That is the mechanism `0.47.9`'s handover named as its lesson, closed at source.
