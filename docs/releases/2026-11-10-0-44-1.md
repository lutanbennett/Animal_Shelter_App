## What shipped, in a sentence

Six release notes. **A button or link you cannot follow is no longer shown** — across the clinic,
enclosure, contacts, diets, medications, donations, stock, memes and system-status pages you now only
see a link when the page behind it would let you in. **The meme maker tags residents while you make

still running.** Settings → Recent changes names a card by its title rather than its internal key, and

**Counted from the entry rather than described from memory:** six notes, one `admin: true`, five plain
strings, no card-tagged note, and `unreleased` empty after the cut.

## Why it does not mail

Lutan asked for it in words, unprompted: *"lets do a minor release, no email and any gaps in testing
noted"*. `major` in this repo means *worth an email*, not semver major, so `major: false` and the
**last** number moves: `0.44.0` → `0.44.1`. The runbook forbids offering "major or minor" as the
question, and it was never asked.

**That one sentence answered both decisions a release normally costs him.** The email was the first;
*any gaps in testing noted* pre-answered the `pending:` test-plan decision that section 3 of the
runbook would otherwise have put to him. `0.43.6` spent a touch on that question and `0.44.0` had it
pre-answered the same way.

**Asserted with a control, not read off the flag:**

```
ok   mail ABSENCE: majorReleasesSince(previous) is empty  [[]]
ok   control: from further back, an older major release is still found  [0.44.0 in ["0.44.0"]]
```

An always-empty function would satisfy the first and fail the second. **On a minor release the
absence check is the one that is easiest to fake**, which is why the pair matters more here than on a
mailing release — and both deploys then said so themselves in their own words (below).

### `--no-mail` was not what stopped UAT mailing, and that is worth knowing

The flag was passed, as the runbook requires. But UAT printed
`deploy: no major release new to uat (was 0.44.0), so no email.` — **the `major: false` check answered
first**, so the flag was never reached. UAT holds a live `RELEASE_MAIL` binding and
`RELEASE_MAIL_ENV ("UAT")`, and **UAT's database holds production's real people**, so the belt and the
braces were both present and the belt is the one that held. **Keep writing `--no-mail` anyway:** on a
mailing release it is the only thing standing between a test site and every real admin's inbox, and a
release manager reading this table should not conclude the flag is redundant.
