## The one-way door, and the check Lutan asked for

**`0277` changes how Admin is recognised**, from matching the role key string `'admin'` to reading
`roles.is_admin`. **Admin holds no cards on production**, so if it had resolved wrongly the only
administrator would have lost Settings → Who does what — the screen needed to undo it.

**It was put to him before the cut and he chose to have Admin verified on production between the apply
and the deploy.** That check ran, and it is the most important line in this record:

```
HARNESS-OK 0277_admin_by_flag_and_profile_photo_medical.sql
  | admin before: true,true,true,true
  | renamed admin after: true,true,true,true
```

`node scripts/check-admin-by-flag.mjs --env production`, **exit read from the command rather than
through a pipe** — which mattered here, because the harness rolls itself back with a `raise exception`
and so prints `status 400` and `Failed to run sql query` on success. Reading the surface would have
called a pass a failure.

**Admin resolves on production even with the Admin role renamed.** The door is closed.

**A second, independent signal that costs nothing:** between the apply and the deploy, production was
running the **previous release's code against the new functions**. `https://lannacare.org/` answered
200 throughout, and `cards-union` and `role-cards-coverage` were both clean in that window. A broken
`has_permission()` would have shown then, before anything was deployed.

## The advisory: one new, four retired

**`npm run audit:prod` exits 1 with one NEW high**, `GHSA-5j98-mcp5-4vw2` — `glob` CLI command
injection via `-c/--cmd`. **It ships unfixed, with a decision file**
(`docs/decisions/2026-10-28-glob-cli-advisory-not-reachable.md`), on two grounds that were checked
rather than assumed:

- **Not reachable.** The flaw is in `glob`'s **binary**, not its library API. Nothing in
  `package.json`, `scripts/` or `worker/` invokes it, and `grep -c 'node-minify' .open-next/worker.js`
  returns **0**. It arrives four levels down a build-time chain.
- **The offered fix is worse than the finding.** `npm audit fix --force` says it `Will install
  @opennextjs/cloudflare@1.20.9` — **older than the 1.20.13 that fixed the four-day cron outage the
  previous evening**. It would trade an unreachable CLI flaw for a repeat of a real one. Second time
  that command has offered to drag the Cloudflare chain backwards.

**The four advisories carried since 2026-10-24 are GONE** — `GHSA-27r3-jxmh-p828`,
`GHSA-4qv8-2p9j-2685`, `GHSA-f72v-6w45-q472`, `GHSA-xjj6-f33q-929c` — resolved incidentally by that
same adapter bump. Confirmed **by grepping each ID** against this release's output rather than by
noticing the package names had changed. `docs/decisions/2026-10-24-audit-body-parser-undici-not-reachable.md`
now describes a state that no longer exists and is kept as history.
