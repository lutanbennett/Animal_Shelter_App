## The boundary this release had, and it is a first

**`0.40.10` is the first double-digit patch number**, and a naive string comparison sorts `"0.40.10"`
**before** `"0.40.9"`. A releases page that sorted as text would have buried this release below the
previous one **with nothing failing anywhere**.

It was checked twice, in two different ways, because the two prove different things:

- `cut-release.mjs --verify` asserted `version is newer than the previous release [0.40.9 -> 0.40.10]`
  and `releases are in compareVersions order`. **That proves the data.**
- The **rendered page** was read on the cut build, signed in as Admin: the first five version strings
  in document order are `0.40.10, 0.40.9, 0.40.8, 0.40.7, 0.40.6`. **That proves the page.**

The assertion alone would not have been enough, and this is the release where the distinction was not
academic.
