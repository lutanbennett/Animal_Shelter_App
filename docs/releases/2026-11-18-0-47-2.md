### Two mistakes of the release manager's own, recorded because neither is visible afterwards

1. **Git Bash lied about line endings and nearly produced a broken release file.** `grep -c $'\r'`
   answered **0** and `od -c` showed only `\n` for `src/lib/releases.ts`, so the first insertion of the
   note was written with LF endings. Node, reading the same file, saw `\r\n` — the MSYS tools strip CR
   in text mode. The insertion was made line-ending aware and the diff came out as **exactly one
   line**, which is the check that caught it. `CLAUDE.md` already carries this trap for `git show`; it
   is wider than that entry suggests.
2. **UAT's Pi build was started without first confirming test's had finished.** The launcher `ssh`
   returning is not the build ending — established ten minutes earlier for production and then not
   applied. Test's build *had* finished, so nothing was harmed and no two builds ever ran at once,
   **but that was luck rather than care**, and two concurrent builds are what the Pi's OOM killer acts
   on. A related fault made it harder to see: a waiter using `pgrep -f "deploy-pi.sh"` matched **its
   own ssh command string** and could never report the build finished. `pgrep -af "deploy-pi[.]sh"` is
   the form that answers honestly.
3. **The terminal panel was trusted once too often.** `read_terminal` showed the same frozen
   `Running TypeScript ...` line while the deploy was in fact running and bundling, which led to one
   report of "it has exited" being repeated after it had stopped being true. **The process table is
   the instrument; the panel is a view that can be stale.**
