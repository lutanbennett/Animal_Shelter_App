## The icon sync works again, after failing on two releases

`sync-home-icons.mjs --env production` exited **1** on `0.48.0` and on `0.47.10`, both times on
*"`PLATFORM_DRIVE_FOLDER_ID` is not set for production"*. **#1841 registered that name this release**,
and the script now runs long enough to be doing real work rather than exiting in seconds. **What was measured, and what was deliberately not waited for.** It drew **536 images across 67 pages**
(45 opened by the 61 cards in `cards.ts`, 22 registry pages no card opens) and uploaded steadily —
`40 / 80 / 120 / 160 / 200 uploaded so far` — still going when this record was written, roughly twelve
minutes in. **The finding is that it RUNS at all**, where on the two previous releases it exited 1 in
seconds; the remaining uploads are network-bound on the Drive API and are routine.

**It was not waited for, on purpose.** The runbook makes this step non-gating in those words — *"If it
fails, say so in the record and carry on: the app page still draws icons in the browser, only the shared
folder is out of date"* — and holding a finished release's paperwork for twenty minutes of file copying
is exactly the cost paperwork rule 5 exists to avoid. **If it does fail partway, that belongs in the next
release's record as a new finding, not here as a retro-fitted one.**

**That also settles what `0.48.0`'s record could only state:** `0.47.9`'s record claimed exit 0 from an
unchanged script, `0.47.10` and `0.48.0` both got exit 1, and the cause was a missing variable all along.
