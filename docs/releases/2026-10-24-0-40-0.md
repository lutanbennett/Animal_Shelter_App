### Closed, and worth noting as a loop closing

**Two faults this session filed yesterday were fixed and shipped in this release** (#886):
`dev-signin.mjs <role>` — the documented form, which had always thrown its own usage error —
now works, confirmed by running it; and `check-home-screens-live.mjs` runs again. The backlog
item was **retitled** to say only part (3) remains, and `--remove` now names the four dev rows
holding the admin login instead of failing opaquely. Filed from a verification round, fixed by
a stream, verified in the next release.

**And one got worse on inspection.** Yesterday's `worktree.mjs done` note was filed as "offers
`--force` on a false premise". The planner traced the cause and found something sharper: because
`done` resolves the folder by name but the branch by branch, **`done <orphan branch name>` can
target a LIVE worktree** — on 2026-10-23 it resolved to the folder holding this session's own
release branch, and `--force` would have destroyed it mid-release **while deleting an unrelated
branch**. Moved to its own `## Architecture` item. **Standing consequence: never pass `--force`
to `done` on a folder whose name does not match its branch**, and a release creates that state
routinely.
