# Temple and community dogs helped — a choice for the Director

*For the Director. Written 2026-10-07. Nothing has been built. Your answer decides what gets built.*

## The question, in one sentence

When the shelter helps a temple or village dog **without taking it in**, what should we write down — so that the website can say "we helped this many" and be telling the truth?

The shelter's app only knows about dogs that live at the shelter. A dog we feed, treat or sterilise at a temple never appears anywhere. So today there is **nothing** behind the website's third number, "temple and community dogs supported".

## Why we are asking first and building second

Once a number is on the public website, it is a promise. If we later change what it counts, the number jumps or drops, and the website has said something different from before. So we want to agree what one "dog helped" means **before** anyone types anything in.

The hard part is this: **if we help the same dog three times, is that one, or three?** Every option below has to answer that, and each answers it differently.

## What already exists (and fits)

You already chose how the other website numbers work: **a starting number and a date typed into Settings, and the app counts forward from that date.** The "animals rehomed" number works this way now.

All three options below start the same way. For everything before the app, you type a starting number and a date. The options differ only in **what happens after that date.**

---

## Option 1 — Starting number only

**What someone types in:** once, in Settings → Website: a number and a date. For example "about 1,200 as of 1 October 2026". Later, you can type a new number whenever you want to update it.

**What the website says:** "About 1,200 temple and community dogs supported."

**One dog helped is:** whatever you had in mind when you chose the number. The app does not decide.
**The same dog helped twice:** the app has no way to know. It depends on how you counted.

**What it gets wrong:** the number never moves by itself. It is only as fresh as the last time someone remembered to update it. Nobody can look back and see *which* outings the number came from.

**Cost:** nothing to build beyond what exists. Can be done almost immediately.

## Option 2 — A short note after each outing

**What someone types in:** after an outing — on a phone, four things, about 30 seconds:
1. Date (today by default)
2. Place (temple or village, picked from a list that grows)
3. What we did — tick any: fed · treated · sterilised · vaccinated · rehomed from a temple
4. How many dogs

Photos are optional.

**What the website says:** "About 1,200 + 85 = 1,285 temple and community dogs helped" — that is, your starting number plus everything the app has been told since the date. The page still says "about".

**One dog helped is:** one dog at one outing. This is really counting **"times we helped a dog"**, and the website wording should say so honestly, for example "dogs helped at our outreach visits".
**The same dog helped twice:** counted twice. The app cannot tell two dogs apart if nobody records which dog it was.

**What it gets wrong:** a dog we feed every week would be counted every week, which would inflate the number. The fix is wording and a rule, not software: for example, only tick "how many dogs" for dogs **new to us at that outing**, or only record outings where treatment was given.

**Cost:** one small table and one phone form. Moderate.

## Option 3 — A card for each dog

**What someone types in:** the first time we help a dog, make a small card: where it lives (temple or village), a photo, a description or ear-notch to recognise it by. Every later help is one line on that dog's card: date and what we did.

**What the website says:** "1,200 + 40 = 1,240 different temple and community dogs helped."

**One dog helped is:** **one dog, ever.** Helped ten times is still one.
**The same dog helped twice:** counted once — as long as someone recognises it and finds its card.

**What it gets wrong:** it only works if staff can recognise each dog. Many temple dogs look alike and nobody sees them twice in the same place. If staff cannot match them, they will make a new card every time, and the number is inflated anyway — only now with much more work. It also needs a person to take a photo and fill in a card at every outing.

**Cost:** the largest. Two tables, photo upload, a search screen.

---

## Our recommendation: Option 2, with the wording kept honest

- It uses the same "starting number plus counting forward" you already chose, so there is nothing new to learn.
- It is quick enough that staff will actually do it on their phones, standing at the temple. Option 3 is the most accurate on paper but the most likely to be abandoned.
- It never claims more than it knows: it counts **help given**, not **different dogs**, and the website can say that.
- If the shelter later wants the "different dogs" number, Option 3 can be added **on top** of Option 2: the outing notes stay valid.

Whichever you choose, we suggest the website says **"about"** and says what it counts.

---

## Questions we need you to answer

Each has our suggested answer, so you can reply "yes to all" or change any of them.

1. **Which option?** (1, 2 or 3.) *Suggested: 2.*
2. **Temple dogs and community dogs — one number or two?** The website mockup has one tile. *Suggested: one tile, but each outing note says "temple" or "village", so we can split it later without losing anything.*
3. **What counts as "helped"?** *Suggested: fed, treated, sterilised, vaccinated, rehomed from a temple.* Are there any you would leave out, for example "fed only"? If "fed only" is left out, the number is smaller but easier to defend.
4. **Same dog, helped again later:** counted again, or only once? (Option 2 counts again unless you tell us a rule; Option 3 counts once.) *Suggested: count again, and say "dogs helped at outreach visits" on the website.*
5. **Who writes the note?** Any staff member on their phone, or only management? *Suggested: any staff, with management able to correct it.*
6. **Photos?** *Suggested: optional, up to a few per outing, not shown publicly unless someone ticks it.*
7. **Starting number and date.** What is the starting number, and what is it true up to? It is an estimate, and the website will say "about".
8. **Should sterilisations at temples be counted here too,** or only in the "sterilisations in local villages" number? Several things could be counted in two numbers. *Suggested: they may appear in both; the two numbers answer different questions.*

## For the developers (not for the Director)

- Fits the existing mechanism: a `community_dogs` row in `impact_baselines` (0156) and a `when` for it in `public_impact_figures`, counting outing rows strictly after `baseline_date`, as `animals_rehomed` does.
- Option 2 is one table of outings (date, place, kind: temple/village, a tick for each kind of help, dog count, optional photo) and one phone form. Option 3 adds a dog table and an event table; 2 does not block 3.
- The public figure stays computed, never stored. The answer to question 4 decides whether the live count is `sum(dog_count)` or `count(distinct dog)`.
- No schema number is reserved by this paper. The schema PR waits for her answer and is its own PR first.
- The answer is recorded as a new file in `docs/decisions/` (`<date>-community-dogs-unit.md`), never appended to `docs/decisions.md`.
