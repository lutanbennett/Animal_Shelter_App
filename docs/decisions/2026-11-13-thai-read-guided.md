# 2026-11-13: how the weekly Thai read is actually done

First run of the weekly read (`#y1dqu`, `#hzmxi`, `#c7zjk`). Written from what happened, not from what was planned.

- **Who judged:** Lutan sat with his wife, who is bilingual. He relayed. So each string had to be readable aloud.
- **How strings were shown:** in chat, never a document (he had said documents were unreadable). One area at a time,
  public-facing areas first, then staff. Each string had three things: where it appears in plain words, the English,
  the Thai. No key paths, no file names.
- **Batch size:** 10 to 15, numbered. He answered a whole batch with one line ("all fine") every time, so the size was
  never a problem. Starting at 8 and moving up was right.
- **Pace:** all 417 in one sitting, 33 batches.
- **What helped:** grouping by screen; saying where on the page a string sits; marking placeholders in the text
  (the list tool prints the stand-in word "one" or "7" where a number or name goes, which looked like a mistake until
  explained, so it was labelled *[number]*).
- **What he changed:** one title (shop staff heading), and one wording rule: permission cards are บัตรสิทธิ์. The rule
  was applied across the whole dictionary, 76 lines, picking out the real permission-card uses by hand.
- **What I would change:** (1) the list script should print placeholders as `{n}`, not as a fake word. (2) The
  dictionary mixed two or three words for "card" and for "supplier"; a short glossary file would catch those before the
  read instead of during it. (3) Ask the glossary-style question (one word everywhere?) once, early, rather than when
  the third variant appears.
- **Open question for the planner (not built):** chat was fast enough. No review screen is needed on this evidence.
  Not tested beyond one sitting of 417 strings.
- **Not touched:** the English dictionary, `RULE_3_BLOCKS`, the manual.
