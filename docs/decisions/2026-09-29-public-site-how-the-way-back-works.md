# 2026-09-29 — Public site: how the way back works

**"Came from the list" is decided by a per-tab record, not `document.referrer` or history length.** `NavTrail` (rendered by `PublicHeader`, so on every public page) keeps the previous public page's path in `sessionStorage`; `BackLink` calls `history.back()` only if that path is the list the link points at (`/adopt`, `/our-work`) and the tab has history, and otherwise it is a plain link to the list. Rejected `document.referrer`: in a Next app it is fixed at the first full page load, so it stays "facebook.com" after the visitor has clicked through to the list and would never restore their scroll. Rejected `history.length`: it counts entries from before the site, so it cannot tell a shared link from a click-through. **Fails safe:** empty or blocked storage, a reload, a modified-click, or a visitor who landed on the detail page directly all fall through to the link, which stays on the site. It also works with no script.

**Breadcrumb is a server-rendered `nav` inside `PublicHeader` (`trail` prop),** Home always first, last step `aria-current="page"`, plus `BreadcrumbList` JSON-LD. A step that is only a heading (Get involved has no page) shows as plain text and is left out of the JSON-LD. Pages with no trail (the home page, /e, /r) show none.

**Two choices left to Lutan, built conservatively:** (1) Desktop keeps the logo as the way home, with no Home entry in the desktop menu, since the breadcrumb and footer now both say Home; the phone menu has one. (2) Phones show no breadcrumb (`hidden sm:block`): the menu's Home and the detail pages' back link do that job. Either is a one-line change.
