# Two release checks that reported a fault where there was none (2026-11-04)

Items `#pte7h` (code-identity check) and `#kvg7d` (`check-test-plan.mjs` and `admin: true`). A check that is known to cry wolf stops being read, which is why `CLAUDE.md` holds `check-test-plan.mjs` strict and why `continue-on-error` must not come back on it. Neither change adds one.

## `#pte7h`: the code-identity check is now an allow-list

- **Where it lives.** Only in `docs/release-procedure.md`. `grep -rn "name-only" scripts/` finds no copy of `git diff <tested>..<deployed> | grep -vE '^(docs/|\.claude/)'` (the hits are unrelated checks). So the fix is a doc edit and there is no script to keep in step.
- **The fault.** The exclude list covered `docs/` and `.claude/` only, so `.github/`, `.githooks/`, `README.md` and most of `scripts/` read as application code. On `0.42.0` it printed eight such files and "Any line means stop" would have halted a sound release.
- **Chosen: INVERT to an allow-list**, `^(src/|worker/|public/|next\.config\.|open-next\.config\.|wrangler\.jsonc$|package(-lock)?\.json$|postcss\.config\.|tsconfig[^/]*\.json$|scripts/pi/|scripts/lib/[^/]+$|scripts/(deploy|apply-migrations|actions-key)\.mjs$)`. None of the eight `0.42.0` files matches it (checked).
- **The brief's premise was too broad, and the allow-list shows why a deny-list of `scripts/` would be wrong.** Part of `scripts/` is not tooling: `deploy-pi.sh` runs `scripts/pi/*` (services, `guard-release.mjs`, `write-env.mjs`, `check-assets.mjs`) and `scripts/actions-key.mjs`/`apply-migrations.mjs` on the Pi, and `deploy.mjs` plus those import `scripts/lib/*.mjs`. A change there is untested code running on a production box, which is exactly what the instruction exists to stop. Excluding `scripts/` wholesale would have traded one false positive for a real false negative. `scripts/lib/backlog-page/` (read only by the backlog page) is the one `scripts/lib` subtree left out.
- **The risk, stated honestly.** A deny-list that is too narrow stops a release for nothing (annoying, caught at once). An allow-list that is too narrow lets untested code through (worse, silent). I chose the allow-list anyway because the list is of things I traced to the build (`wrangler.jsonc` `main`/`assets`, `next.config.ts`, the `deploy-pi.sh` call graph) and because a deny-list rots in the direction of crying wolf, which is how this check was ignored in the first place. To pay for the silent direction, the runbook now tells the release manager to **run the same diff with `grep -vE` and read what it prints**; a file in that set that is built or run at deploy gets added to the list in the same change. A new kind of file is therefore reported as not built, and visible, rather than halting a release.
- **Not covered, deliberately:** `supabase/migrations/` (applied by `apply-migrations.mjs` and gated by its own drift check, not part of a build's code identity) and `.github/workflows/` (CI, not deployed).
- **"Any line means stop" is kept.** Old: *"Any line means stop — something outside documentation is in one build and not another, which is untested code on a production box…"* New: *"Any line means stop — something that is built or run at deploy is in one build and not another, which is untested code on a production box…"* The instruction is the same; only which lines reach it changed.
- **Not done:** the item's optional suggestion that `deploy.mjs` print the SHA it builds from beside the requested release SHA. It is a separate change to a deploy script and was not asked for in the brief.

## `#kvg7d`: `admin: true` is a third tag state

- **Cause.** `check-test-plan.mjs` built its set of tagged notes from `{ text: …, roles|cards … }` only, so an `admin: true` note was never in the set, matched `ADMIN_ONLY_NOTE`, and was reported as one every role will see. It is the most tightly targeted note there is.
- **Fix belongs at the tag set, not at the warning.** Admin holds no card, so no card tag can express "Admin only", and re-tagging was never an option. The tag regex now accepts `admin\s*:\s*true` beside `roles|cards`. `ADMIN_ONLY_NOTE` and the warning's condition are untouched, so nothing the checker flagged before is newly accepted except a note that carries `admin: true`. The `roles` tag set (closed to new notes) is unchanged.
- **Shape.** The three small functions moved to `scripts/lib/release-note-tags.mjs` so a test can call them; the checker runs at import and cannot be unit-tested otherwise. `scripts/release-note-tags.test.mjs` (picked up by the existing `scripts/*.test.mjs` glob) covers: `admin: true` addressed; `cards`/`roles` still addressed; plain note still warned; `admin: false` and `administrator: true` still warned; a neighbour's tag does not leak.
- **Reaches other streams on merge.** Strictly a false-positive fix. `continue-on-error` is not touched.
