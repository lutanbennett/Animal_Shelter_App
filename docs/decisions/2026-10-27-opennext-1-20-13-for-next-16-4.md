# Bump @opennextjs/cloudflare to 1.20.13: Next 16.4 needs it (2026-10-27)

The 15-minute cron died on 2026-10-23 on test and production. The heartbeat from
`2026-10-27-cron-heartbeat.md` showed the trigger firing and both stages failing with
`Unexpected loadManifest(/.next/server/preview-props.json) call!`.

**Cause, with its evidence.** `942ea49f` (2026-10-23 04:57 UTC) bumped `next` 16.3.8 to 16.4.2,
and shipped in release 0.39.4 shortly before the last cron run. Next 16.4 added
`server/preview-props.json`. Adapter 1.20.6's `load-manifest.js` patch does not list it and throws.
Adapter 1.20.13's patch lists it ("Next 16.4+") and its peer range is `next >=16.4.1` for Next 16.
The Worker's own copy of the app is rarely used (the Pi serves pages), so the cron was the only
daily caller and the only thing that showed it.

**Change.** `@opennextjs/cloudflare` ^1.20.13. Pulled forward with it: `@opennextjs/aws` 4.1.4 to
4.1.12, `wrangler` 4.145.0 to 4.153.0, `workerd` and `esbuild`. `next` is unchanged.

**Verified:** `gates.mjs` typecheck/lint/test/build all 0; `npm run opennext:build` completes and
the built `handler.mjs` lists `.next/server/preview-props.json`.

**NOT verified:** that the cron then runs. That needs a Worker deploy, which is Lutan's. A real run
shows as `verdict: healthy` in `node scripts/check-production.mjs calendar-cron --env test`.
Also not exercised: a wrangler deploy on 4.153.0 (the earlier `Cron schedules: fetch failed`
partial-trigger error seen on test is a separate matter this does not claim to fix).
