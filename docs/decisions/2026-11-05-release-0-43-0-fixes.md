# 2026-11-05 — the three 0.43.0 faults

Branch `claude/release-0-43-0-fixes`. **None of this is live until the Pi is deployed, which is Lutan's step.**

## 1. Who does what returned a server error

`CreateRoleForm` is a client component and the page passed it `keyIs`, a **function** (`en.ts`/`th.ts`). A function cannot cross from a server component to a client one, so the page threw. The label is computed on the client as the role name is typed, so it was **not** made a server action: it is now a string with `{key}` in it (`en.ts`, `th.ts`) and `CreateRoleForm` does `labels.keyIs.replace("{key}", key)`.

The other client components on the page (`CardBoard`, `CardControls`, `FeaturesPanel`) were read: every prop they take is a string, number, boolean or plain data, no function.

**Why nothing caught it.** `CreateRoleForm` renders only when `canEdit` = Admin **and** the authenticator step is done. A `dev-signin.mjs` session is aal1, so no dev check, browser pass or CI run can render it; the page returned 200 under `next dev` and a production build. **What can check a component only an aal2 Admin can render? Nothing automatic.** It goes on the release smoke test: an Admin who has verified opens Settings → Who does what and sees the Create a role box. (Left in the test plan's manual table for the same reason.)

## 2. Publish on an adoption update saved nothing

`saveAdoptionUpdate` validated `sharePublicly`, `publicStory` and `publicFirstName` and then built `row` without them. They are now in `row`. Column names and checks come from `0214` (`share_publicly boolean not null default false`, `public_story text`, `public_first_name text` with a one-word, 1–40 character check). No other code writes these columns (grepped `src`, `worker`, `scripts`); the 0.43.0 media-approval step works on `attachments`, so there is nothing to fight. Policies are unchanged: the write goes through the table's existing `resident.adoption_news` policy.

**A second fault in the same function**: the first-name check was `/s/` (the letter s) where it meant `/\s/` (whitespace), so a name such as "Susan" was refused. Fixed in the same change.

`scripts/check-adoption-publish-roundtrip.mjs` is the round-trip check: it asserts the action's `row` names all three columns, then writes a row with all three on dev, reads it back, and rolls back. "Susan" is the test value so the regex fault is covered too. It does not call the server action itself (that needs a session); the source assertion is what ties the action to the columns.

## 3. Menu entry for the approval page

`NavLinks` has a new `canApprove` prop, set in `NavPane` to `can(perms, "photos.approve") || can(perms, "website.approve")` (the activities `/photos/approve/page.tsx` asks). Admin passes both through the `isAdmin` short-circuit in `can.ts` and holds no card. No role, `isAdmin` or card key is named in the menu code. The entry reads "Photos to approve" and sits beside Management/Settings.
