# 2026-10-14 — SEO audit: the canonical host rule, what the site claims about the shelter, and what waits for go-live day

Stream `claude/seo-audit-fable`, the backlog item *Search engine optimisation of the public website
before go-live*. The report is `docs/seo-audit-2026-10-14.md`; this file is the part of it a later
session needs without reading the report.

## The canonical host rule: no address is written in, every address follows the request

Every absolute address the public site emits — the `canonical` link, Open Graph `url` and pictures,
the JSON-LD `url`, `logo`, `image` and `mainEntityOfPage`, the sitemap, robots.txt's `Sitemap:` —
is built on `getSiteOrigin()` (`src/lib/site-origin.ts`): `NEXT_PUBLIC_SITE_URL` when set, else
the host the request arrived on. The canonical is written as a relative path (`/adopt`) and Next
makes it absolute through `metadataBase`, which is the same origin. So the move to
`lannacareforanimals.org` changes nothing in these files, and a grep for either hostname in `src/`
still finds only comments (the 2026-10-10 domain rule, and `2026-10-14-public-site-findability.md`).

The canonical is always the **bare path**: `/adopt` for `/adopt?ready=1`, `/our-work` for
`/our-work?category=Rescues`. The filters are views of one page, not pages.

**`hreflang` is deliberately absent.** English and Thai share one address (the language is a
cookie), so there is no Thai URL to name, and an `hreflang` pair pointing at the same URL would
tell Google the English page *is* the Thai page. It arrives with the *Give the Thai site its own
addresses* item, after the cutover, as `alternates.languages` on every public page.

## Metadata is not streamed, for anyone

`htmlLimitedBots: /.*/` in `next.config.ts`. Next's default streams `generateMetadata`'s output
into the `<body>` after the page for any user agent not on its bot list, which is a speed trick
that costs nothing for Googlebot (it renders the page) but leaves the `<head>` of the raw HTML
without a title, description or canonical for anything that does not. Lighthouse 12 removed
"Chrome-Lighthouse" from its user agent, so Google's own PageSpeed Insights reported "no meta
description" on every page and scored the site 92; link checkers and any raw-HTML reader saw the
same. Measured by fetching the home page with three user agents: the description sat at byte
2,621 (in `<head>`) for a "Chrome-Lighthouse" UA and at byte 25,000+ (in `<body>`) for plain
Chrome and for Googlebot's UA.

The cost is that the response waits for `generateMetadata`. The public pages' metadata reads the
same `site_content` and resident/story rows the page itself reads, and the staff pages' metadata
is static, so no page waits on anything it was not already waiting on. Measured after the change:
the SEO score is 100 on every public page type (the report's Scores table).

## What the site claims about the shelter, and from where

Every machine-facing fact comes from Settings → Website (`site_content`) or the dictionary, and
nothing is typed a second time:

- **`AnimalShelter`** (home page, since #607): name, tagline as description, origin as `url`,
  the logo, the hero as `image`, the address, phone, email and map link as typed, visiting hours
  as typed (free text, which schema.org's `openingHours` allows; the `Mo-Su 09:00-16:00` form would
  be a guess), and `sameAs` with the Facebook, Instagram and X links **and, new today, the LINE
  Official Account's add-friend page** (`lineLink()`), because schema.org has no LINE property and
  a profile page is what `sameAs` is for.
- **`WebSite`** (home page, new): name, origin, language. This is what Google reads to show the
  site's name in a result instead of its domain.
- **`Article`** (each story, new): headline, the summary's opening line (or the dictionary's
  fallback), the cover or the site's default picture, `datePublished` from the story's date,
  the shelter as author and publisher with the logo. The one shape Google shows a rich result
  for that fits a story.
- **`BreadcrumbList`** (inner pages, unchanged).
- **No per-animal schema**, on purpose: schema.org has no type for an animal for adoption that a
  search engine shows, and the nearest (`Product` / `Offer`) describes a dog as goods for sale.

All of it is written by `jsonLdString()` in `src/lib/site/share.ts`, which escapes `<` as `<`
so a `</script>` in an admin's text cannot end the element. Before today the `AnimalShelter`
string did `.replace(/</g, "<")`, a no-op; the breadcrumb already escaped correctly.

## Photos in three sizes, chosen by the browser

`PHOTO_WIDTHS` gains **800** (160, 400, 800, 1200). `src/components/PublicPhoto.tsx` renders a
plain `<img>` with `srcset` of the 400, 800 and 1200 renditions and a `sizes` attribute per
layout, replacing `next/image fill` on the home hero and featured animal, the animal and story
galleries, and the resident, story and happy-endings cards. `images.unoptimized` stays on (no
`/_next/image` on Workers), which is why `next/image` could never emit a `srcset` here
(`2026-10-01-public-photo-sizing.md` left exactly this for later). The page's first photo is
`priority`: eager, `fetchpriority=high`, and a `<link rel=preload imagesrcset>` through React's
`preload()`, which is what `next/image priority` did. Thumbnails stay at 160. Nothing on a staff
page changes; the 800 rendition is one more file per photo in the Pi's disk cache and the edge cache.

## Smaller things, so nobody re-derives them

- `/login` and its two sub-pages are `noindex` through a new `src/app/login/layout.tsx`: every
  public page links to them as *Staff login*, and once the site is open Google would list them.
- `SiteBody` takes a `headingLevel`: a page body under the page's `h1` renders "## " lines as
  `h2`; the home story and the "How adoption works" box, which sit under an `h2`, keep `h3`. Five
  pages went `h1 → h3` before and failed the accessibility heading-order audit.
- The adoption list's "ready for adoption" chip is a link, so it marks itself with `aria-current`
  like the species chips, not `aria-pressed` (not allowed on a link; the one accessibility failure
  on `/adopt`).
- `robots.ts` and `sitemap.ts` were not touched. Locked, both still answer "nothing", as #607 built.

## Left for go-live day, and why

The site is locked until the Director has approved its words, and nothing here unlocks it. What
cannot be done against a locked site, written into the cutover item as steps:

- **Google Search Console** for `lannacareforanimals.org` (a Domain property, verified by a TXT
  record in Cloudflare), then the sitemap submitted and the home and one animal page inspected.
- **Rich Results Test** and **PageSpeed Insights**, both of which need a public URL.
- **Facebook's and LINE's preview tools**, same reason; the tags were verified by reading the
  rendered HTML.
- **A Google Business Profile**: not code, the Director's or Lutan's to claim, with the name,
  address, phone and hours exactly as Settings → Website has them.
- **Thai wording** for the four Settings → Website pages that are English today, through the
  translation queue; proposals in the report, the Director's to correct.
